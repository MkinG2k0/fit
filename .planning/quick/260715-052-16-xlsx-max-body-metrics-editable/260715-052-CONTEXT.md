<domain>
## Task Boundary

Новая фича «таблица нагрузок» по образцу `Жим.xlsx`: пользователь добавляет упражнения каталога в фичу, задаёт MAX и макс. повторы, вес тела берёт/пишет в `/body-metrics`, после чего видит фиксированную 16-недельную таблицу (% / кг / повторы + оценки 1ПМ по формулам Бржыки / Эйпли / Лэндера).

</domain>

<decisions>
## Implementation Decisions

### Источник «веса» (Q1 = 2)
- **Вес** = вес тела (`weightKg` в body-metrics), не рабочий вес на штанге.
- При первом добавлении упражнения в фичу: пользователь вводит макс. повторы и вес тела; вес один раз создаёт запись в body-metrics (`addEntry` с `weightKg`).
- На экране таблицы вес тела **только читается** из последнего значения body-metrics (не редактируется здесь). Рабочий вес недели считается отдельно от MAX.

### MAX для процентов (Q2 = 2)
- **MAX** — отдельное пользовательское поле на упражнение в фиче (программный максимум для колонки `%` / `вес кг`).
- Не вычисляется автоматически из формул Т.Макс.
- `вес кг` недели = `MAX * (вес% / 100)` с округлением как в Excel (шаг 0.5 кг: 37.5, 39.0, …).

### Шаблон таблицы (Q3 = 1)
- Жёстко как в `Жим.xlsx`: 16 недель, те же `вес %` и `раз` на каждую неделю.
- Колонки: Неделя | вес % | вес кг | раз | Ф. Бржыки | Ф. Эйпли | Ф. Лэндера | &lt;avg&gt;
- Формулы 1ПМ на строке недели считают от **рабочего веса недели** и **повторов недели** (не от веса тела).

### Подпись «3 подхода / 2 раза в неделю» (Q4 = 1)
- Только UI-подсказка/подпись, без логики расписания.

### Навигация (Q5 = 1)
- Новый роут + пункт меню (рядом с аналитикой / параметры тела), например `/load-table` или `/training-cycle`.
- Заголовок страницы в `AppLayout` PAGE_TITLES.

### Несколько упражнений (Q6 = 1)
- Список упражнений в фиче.
- У каждого: `catalogExerciseId`, `maxReps` (editable на экране детали), `maxKg` / MAX (пользовательский).
- Вес тела общий — последнее `weightKg` из body-metrics.

### Claude's Discretion
- Точный slug роута и label в меню.
- Persist: Zustand + localStorage (как body-metrics / exercise-store).
- FSD: entity store + feature UI + page + route/nav.
- Нужен ли блок «Т. Макс» снизу (Бржыки/Эйпли/Лэндер от вес тела × maxReps): **не строить от веса тела** (бессмысленно для жима); опционально показать avg формул по текущей/выбранной неделе или скрыть — предпочтительно колонки в таблице недель достаточно.
- При добавлении: если последнее `weightKg` уже есть — можно префиллить поле веса и всё равно писать новую запись только если пользователь ввёл значение (или всегда писать новую запись при confirm, как сказал пользователь «создаём запись»).
- MAX на экране детали: editable (иначе нет способа скорректировать программу).

</decisions>

## Specific Ideas

Фиксированный 16-недельный шаблон из Excel:

| Неделя | вес % | раз |
|--------|-------|-----|
| 1 | 75 | 5 |
| 2 | 78 | 5 |
| 3 | 82 | 5 |
| 4 | 85 | 5 |
| 5 | 88 | 3 |
| 6 | 92 | 3 |
| 7 | 95 | 2 |
| 8 | 98 | 2 |
| 9 | 82 | 5 |
| 10 | 85 | 5 |
| 11 | 88 | 5 |
| 12 | 92 | 5 |
| 13 | 95 | 3 |
| 14 | 98 | 3 |
| 15 | 102 | 2 |
| 16 | 105 | 2 |

Формулы (w = вес кг недели, r = раз):
- Бржыки: `w * 36 / (37 - r)`
- Эйпли: `w * (1 + r/30)`
- Лэндер: `(100 * w) / (101.3 - 2.67123 * r)`
- avg = среднее трёх
