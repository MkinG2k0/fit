  <action>
Установить и подключить готовый countdown на deadline (не setInterval-countdown как источник истины).

Пакет (обязательно pnpm):
- `pnpm add react-timer-hook`
- Использовать `useTimer` из `react-timer-hook` с `expiryTimestamp` (Date конца), `onExpire`, `autoStart` — это заменяет баговый nested `setSeconds`/`setMinutes` в текущем `src/features/timer/lib/useTimer.ts`.

Zustand store `src/features/timer/slice/restTimerStore.ts` (persist через `createJSONStorage(() => zustandAppStorage)` как в userStore):
- Состояние: `endAt: number | null` (epoch ms), `durationSec: number` (текущая сконфигурированная длина для ручного старта на /timer; default 120), опционально `pausedRemainingMs: number | null` если нужна пауза.
- Actions: `start(durationSec: number)` → `endAt = Date.now() + durationSec * 1000` (перезапуск при уже идущем таймере); `clear()` → `endAt = null`; `setDurationSec`; при необходимости `pause`/`resume` через сохранение remaining и новый endAt (сохранить UX кнопок Старт/Пауза/Сброс на TimerControls).
- Источник истины для remaining: `Math.max(0, endAt - Date.now())`. Persist `endAt`, чтобы таймер пережил закрытие вкладки/перезагрузку приложения и корректно догонял время при возврате.

Переписать `useTimer` / `timer.tsx`:
- Убрать custom interval-логику с nested setState (текущие баги: дрейф в фоне, гонки при 0:00, seconds→59 при minutes=0).
- UI подписывается на store: если `endAt` активен — `useTimer({ expiryTimestamp: new Date(endAt), autoStart: true, onExpire })` из либы; иначе idle с editable duration.
- `onExpire`: один раз вызвать `playNotificationSound` + `sendPushNotification`, затем `clear()` store. Добавить guard от двойного fire (ref или store flag).
- Сохранить круговой UI TimerDisplay / controls, но передавать remaining из deadline, не из локального interval state.
- При старте с /timer: читать duration из store/UI и вызывать `restTimerStore.start(sec)`.

Barrel: экспортировать store + нужные хелперы из `src/features/timer/index.ts`.
