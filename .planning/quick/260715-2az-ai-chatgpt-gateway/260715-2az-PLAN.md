## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → AI gateway | Untrusted network to local OpenAI-compatible gateway; API key and workout log leave the device |
| Vite env → client bundle | `VITE_*` secrets are embeddable in the frontend build |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-2az-01 | Information Disclosure | VITE_AI_GATEWAY_API_KEY in client | medium | accept | Locked local-gateway design; key only for localhost; never log/print key values in UI, SUMMARY, or commit messages; `.env.example` uses placeholder only |
| T-2az-02 | Information Disclosure | workout log in prompt body | low | accept | Local-first personal data to user’s own gateway; no medical claims in prompt |
| T-2az-03 | Spoofing | gateway auth header | low | mitigate | Send Bearer and/or X-API-Key when key set; surface `{ message, code, status }` errors without raw secret leakage |
| T-2az-SC | Tampering | package installs | high | accept | No new npm packages — use existing axios |
</threat_model>

Env (D-05):
- Edit `.env`: add `VITE_AI_GATEWAY_URL=http://localhost:3005`. Also add `VITE_AI_GATEWAY_API_KEY=` set to the same value as existing non-Vite `API_KEY` if present (do not invent a new secret). Never print the key value in commits, SUMMARY, or logs.
- Create or update `.env.example` with `VITE_AI_GATEWAY_URL=http://localhost:3005` and `VITE_AI_GATEWAY_API_KEY=your-api-key-here` (placeholder only). Document that the frontend reads `import.meta.env.VITE_AI_GATEWAY_URL` and `import.meta.env.VITE_AI_GATEWAY_API_KEY`.
- Extend `src/vite-env.d.ts` Interface ImportMetaEnv with optional string fields for those two VITE vars.

Gateway client (D-04) — new file `src/shared/api/aiGateway.ts`, re-export from `src/shared/api/index.ts`:
- Separate client from `$api` (different base URL). Prefer axios.create with `baseURL: import.meta.env.VITE_AI_GATEWAY_URL`.
- Export `createChatCompletion(messages: { role: string; content: string }[])` that POSTs `/v1/chat/completions` with body `{ model: "gpt-4o-mini", messages }`. Stream is not supported — do not send stream:true.
- Auth: if `VITE_AI_GATEWAY_API_KEY` is non-empty, set `Authorization: Bearer &lt;key&gt;` and also `X-API-Key: &lt;key&gt;` (gateway accepts either).
- On HTTP error, throw a small typed error or object preserving gateway shape `{ message, code, status }` from response data when present; otherwise a clear Russian fallback message. Never include the API key in error strings.

Feature model/lib under `src/features/aiRecommendations/` (D-01, D-07):
- `model/types.ts`: period union e.g. `last_workout | week | month | all` with Russian labels for UI.
- `lib/filterDaysByPeriod.ts`: input `Record&lt;string, CalendarDay&gt;` (keys `DD-MM-YYYY` as in storage) + period + now (dayjs). Rules:
  - last_workout: single most recent day that has at least one exercise with a logged set (reps&gt;0 or weight&gt;0); if none, empty.
  - week: days from today−6 through today inclusive (rolling 7 calendar days).
  - month: days from today−29 through today inclusive (rolling 30 days).
  - all: all days with any exercises.
  Skip empty shell days with no logged sets when building the payload (except still allow empty result detection).
- `lib/buildWorkoutLogText.ts`: format filtered days as readable Russian plain text: date line, exercise name, then sets as `вес × повторы` (e.g. `60 кг × 8`). Return empty string when nothing to send.
- `lib/prompts.ts`: invent a solid Russian system prompt for a beginner gym coach assistant: analyze weight/reps logs, give actionable progressive-overload / technique / recovery tips, stay practical, explicitly avoid medical diagnosis and injury treatment. Export helpers `getSystemPrompt()` and `buildUserPrompt(periodLabel, workoutLogText)` that wrap the log and ask for concrete next-session recommendations in Russian.
- Barrel `index.ts` exporting public API needed by the page (types + builders + later UI will add).

Do not call the network from these pure helpers. Reuse `CalendarDay` / `Exercise` / `ExerciseSet` types from entities. Prefer `readAllTrainingDaysFromStorage` from analyticsStorage at the UI layer (next task), not here.
